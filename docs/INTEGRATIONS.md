# Service connections

Change values only in the private `.env` generated by setup, then restart the application. Do not expose that file through a web server or repository. Credentials in frontend JavaScript are not used, except the payment provider's intentionally public key ID and short-lived TURN credentials.

## Password reset email

Set `EMAIL_HOST`, `EMAIL_PORT=587`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` and `DEFAULT_FROM_EMAIL` using an SMTP provider and a verified sender. TLS is enabled. Set `PUBLIC_ORIGIN` to the exact user-facing origin so reset links reach the correct site. Local review can use `http://127.0.0.1:8000`; production requires your approved HTTPS custom domain.

No email provider account has been created or connected in this build. Verify delivery, spam placement and a complete reset flow before launch. Reset requests show a generic response to avoid exposing which accounts exist. Links expire after 30 minutes. Password changes invalidate other sessions.

## Private video calls

The browser uses WebRTC. Django carries only authorized signaling messages; it does not receive or record media. Both accounts must belong to the confirmed video appointment. One call tab per participant is supported.

For actual cross-network use, configure a TURN service that supports coturn-compatible REST/HMAC-SHA1 temporary credentials:

- `TURN_URL`: your authenticated TURN URLs, comma-separated, e.g. `turns:relay.yourdomain.example:5349?transport=tcp`
- `TURN_SECRET`: the TURN service's shared authentication secret

The backend generates credentials expiring after one hour. The browser receives those short-lived credentials, not the shared secret. With TURN configured, `iceTransportPolicy=relay` is used. In local mode without TURN, calls are limited to network conditions that permit direct communication. Production refuses to start video without TURN configuration.

Use valid HTTPS for browser camera/microphone access outside localhost. Test doctor/patient join order, denied camera permission, reconnects, mobile browsers, different networks, call end and expired access. Real two-device audio/video was **not** verified in this environment. This version does not include recording, screen sharing, chat or calendar invitations.

Schedule `manage.py cleanup_transient` every 5 minutes to remove old signaling and expired limits/sessions. It does not delete clinical records.

## Consultation payments

Cash/bank payment records work without a gateway. Staff must independently verify actual receipt before recording it. The form is a record, not a money-transfer operation.

To enable online payment, set `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` and `RAZORPAY_WEBHOOK_SECRET`. Use provider test mode first. Configure automatic capture and a `payment.captured` webhook at:

`https://YOUR-APPROVED-DOMAIN/api/payments/webhook/`

Order amount/currency come from the appointment's stored database fee. Client fees are ignored. Server-side HMAC validation and captured-payment verification are required before marking an order paid. Webhooks validate their HMAC and captured amount/currency. Provider callbacks are idempotent.

No real merchant account, transaction, refund or subscription has been created. Refunds are handled by the hospital/provider outside this application and then recorded with a verified reference. Payment provider charges and account approval depend on the merchant's current provider terms. There is no automatic refund API in this version.

Razorpay scripts and frames are allowed only on the explicit payment page. Most pages keep a strict self-only Content Security Policy. Test Checkout in the target browser because provider domains/requirements may evolve.

## Medical PDF upload

JPEG/PNG uploads up to 5 MB work without a scanner and are re-encoded to remove metadata and non-image content. Other file types are rejected. Uploaded reports are private downloads, not publicly served files.

Install and maintain ClamAV and set `CLAMAV_COMMAND` to the absolute path of `clamscan`. Keep its malware definitions current. PDFs are accepted only when scanning succeeds; an unavailable scanner or failed scan rejects the upload. This scan is one control, not a guarantee of a harmless document.

## Hospital contact buttons

Enter verified hospital and ambulance phone numbers in Admin → Hospital settings. The buttons use `tel:` links; they open the device dialer and do not dispatch an ambulance automatically.
