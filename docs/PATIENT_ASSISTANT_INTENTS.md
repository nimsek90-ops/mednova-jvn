# Patient assistant intent catalogue

All factual answers come from the existing database or approved FAQ/settings. No provider is required. Chat JSON is `/api/assistant/`; actions finish through authorized portal endpoints.

| Intent | Example | Data/tool | Authentication | Success | Error / missing data | Handoff condition |
|---|---|---|---|---|---|---|
| Doctor search | “skin doctor tomorrow”, “heart specialist” | Approved DoctorProfile + Department; `available_slots(doctor_ids=…)`; ScheduleSession | Public | Real doctor cards, hours, fee, matching live times | No matching doctor; registered but no matching slot; unavailable live service | Persistent unexplained booking conflict → appointments team |
| Time/mode follow-up | “which one tomorrow morning?”, “after 5 pm”, “same doctor”, “video” | Session profile/specialty/date/time/mode context; shared scheduling | Public search; patient booking | Filters the same verified doctor set | AM/PM clarification; no matching slot | Patient requests further help |
| Booking/follow-up visit | “book with this doctor” | Returned slot link → existing booking form → atomic `book` service | Approved patient/receptionist at existing booking endpoint | Actual backend appointment/confirmation page after explicit submit | Slot taken, overlapping visit, notice/capacity/approval restrictions | Unresolved conflict → appointments case |
| Own appointments | “what time is my appointment?”, “my next appointment” | Appointment filtered by authenticated patient; actual doctor/profile | Approved patient | Own date/time/status/department/location/actions | No own matching visit; login prompt | Unexplained cancellation, missing visit, delay |
| Reschedule / cancel | “reschedule my visit”, “cancel appointment” | Own appointment links → existing confirmation forms and services | Approved patient; existing role rules apply | Backend returns actual updated visit | Ineligible status/time/payment restriction; no silent change | Staff decision required → appointments |
| Reports / investigations | “is my blood report ready?”, “latest results” | Own Report and Investigation; private download/clinical endpoints | Approved patient | Actual uploaded files/status and secure links | No linked record; no stored ETA; download troubleshooting | Missing, delayed or failed access → assigned clinician; wrong-patient link → privacy |
| Prescription / dispensing | “what was prescribed?”, “prescription processed?” | Own Prescription + items, clinician instructions and dispensing counts | Approved patient | Recorded directions and actual dispensing state | No record; no generated dose/medicine recommendation | Availability/access concern → pharmacy; diagnosis/treatment decision → clinical team |
| Billing / receipt | “outstanding bill”, “payment received?”, “refund?” | Own Payment and existing receipt/pay pages | Approved patient | Recorded consultation balances/status/receipt; configured payment link | No billing row; no invented insurance/refund approval | Dispute or unreceived payment → billing |
| Admission | “my admission status”, “my bed” | Own Admission, bed, department and doctor | Approved patient | Actual status/location | No admission/bed assigned | Staff-only admission/discharge decision → hospital team |
| Queue | “waiting for a long time” | Own today's QueueEntry | Approved patient | Actual token/status | No check-in token; no reliable ETA stored | Delay unresolved → reception |
| Preparation / hospital policy | “what should I bring?”, “video preparation”, “address” | Approved language-specific HospitalFAQ, Hospital settings, existing portal workflow | Public policy; private visit requires login | Published facts and applicable workflow links | Explicitly unpublished; no guessed fasting/medicine instructions | Appropriate staff contact |
| Case preparation | “real person”, “cannot download”, “billing dispute” | Reviewable session draft with patient claim, timestamps and unambiguous owned reference | Approved patient | Review link; no success claim/case before consent | Login prompt; edit/choose relevant visit if unclear | Patient confirms sharing with selected team |
| Case creation / status | “my case status”, patient-reviewed support form | SupportCase unique request key and ownership; SupportMessage | Approved patient for own case; restricted staff roles | Persisted case reference/status and portal conversation | Wrong-user ID → 404; invalid/unauthorized form; transient database → 503 | Admin routes eligible worker using metadata |
| Staff replies / notes / routing | Staff queue/status forms | `care.support`, locked transactions, portal Notification, AuditEvent | Team roles; medical case assigned doctor; admin medical metadata only | Stored replies/internal notes, actual status/assignment | Cross-access-group transfer rejected; patient cannot see internal notes | New audience requires new patient consent |
| Clinical / privacy / safeguarding | “diagnose me”, “not my report”, “report abuse” | Safe limits + reviewed clinical/privacy case | Login for case | Qualified team review offered, no diagnosis | No case before consent; clinical data not disclosed to reception | Assigned clinician / privacy administrator |
| Emergency priority | Emergency phrases, severe bleeding, breathing difficulty | Immediate emergency copy; verified hospital emergency contact when available | Public | Immediate urgent guidance; no dispatch claim | Normal tools/tickets must not replace emergency advice | Emergency care immediately, not queue waiting |

Privacy: routine raw questions/private result cards are not retained in history. Unresolved issue/draft context is limited to the private session and expires after 30 minutes of inactivity. Only reviewed, consented case summaries become persistent support records. No patient IDs or confidential records are sent to an external provider.
